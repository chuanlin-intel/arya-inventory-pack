## If-then rules
| If | Then |
|---|---|
| The m365 client is not signed in (D7 check fails) | Stop that branch, show the owner `& <m365> auth login` (full path); continue other branches |
| Step 2 finds no unread reminder in the last 14 days | Repeat step 2 read-only without `--unread-only` and with `--since` 180 days back; log it. Never mark anything read here |
| Step 2 finds no reminder email at all, or the mail branch is stopped | Build the parser from the TASK.md text sample only; log it in Surprises |
| The real HTML differs from the TASK.md text sample | Follow the real HTML; fixtures copy its structure with fake values |
| The `--from Intellabs_Support_Services` filter returns nothing but unfiltered inbox listing shows such mail | Drop `--from`, filter by the sender local part in the parser only; log it |
| No token is available for step 4 and A2 is refused or not done | Write the field mapping as a QUESTIONS.md entry, keep `ticket_config.json` with `"resolved": false` and D13 names, skip steps 4b and 10, continue all others |
| Issue type `Support Request` does not exist in NEXUIE | Use the issue type of NEXUIE-142951, log it |
| Pack lint prints an `ERROR:` | Fix it per the rule it names; never edit `<acs>` |
| Route test does not return `x-inventory-extend` | Reword per F9/F10, at most 3 tries; then record in Surprises and continue |
| `powershell.exe` blocks the script by execution policy | Use `-ExecutionPolicy Bypass` on that command line only; never change the machine or user policy |
| An approval is refused | Skip that step and every step that depends on it; mark them `skipped (refused)` in STATUS.md |
| A4 or A5 target already exists | A4: add the line only if no line equals `C:\arya-inventory-pack\pack` (case-insensitive, trailing `\` ignored). A5: if the path is already a junction to `<entry>`, do nothing; if anything else exists there, stop step 9 and record it; never delete or replace it |
